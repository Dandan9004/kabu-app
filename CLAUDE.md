# 株アプリ（仮名）

Japanese-stock app for the owner's Galaxy Z Fold8. Kotlin + Jetpack Compose, one module (`app`), plus a data
pipeline (`pipeline/`, Python) that will run on GitHub Actions. Started 2026-11-07; the earlier 株助言アプリ was
dropped for being thin, hard to read and weak in its advice.

The owner talks in casual Japanese and calls Claude 「相棒」; reply in Japanese and call yourself 「僕」. They decide
the look by seeing it; keep the design canvas in step: https://claude.ai/artifact/NeLesmVvEytc9g4jxuJ3pJ

Build like the launcher: `JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"` then `gradlew assembleDebug`;
adb is `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`. Keep the path ASCII-only.

## Owner decisions (2026-11-07; don't change without asking)

- Japanese stocks first, US later. Separate app from the launcher (a launcher widget may come later).
- Weekly: 10 trending stocks by how many outlets covered them; at most 5 per industry (TSE 33 sectors,
  semiconductor-related counted as one). Picked by code, not by the AI.
- 7 experts + まとめ役 on the Pro plan (Claude routine), no paid API. Scores 1–5, 5 best. 「会社の力」 (from 目利き・
  決算・成長・業界・株主) and 「割安さ」 (値段の番人 + PER/PBR; 5 = cheap) are separate. 反対役 gives no score: it is the
  「弱点」 card (重さ 大/中/小, three points).
- Rule-based scores, no AI: 数字の点 (fundamentals, sector-relative) and 投資家の点 (EDINET 大量保有; none = 「動きなし」).
- News: outlet-count order + TDnet disclosures always. No Yahoo! scraping.
- Holdings: codes only, stored on the phone only. 7-expert review of a holding only when asked on Discord.
- Track record: price on the rating day vs 1 and 3 months later, against the Nikkei. No virtual trading.
- Free unofficial price source; on failure, banner in the app + Discord, then find another free source together.
- Wording never recommends buying or selling; a one-time disclaimer card.

## Design rules

Launcher colors (beige `#E8DCC4`, navy `#1E2A44`, tiles `#D3C2A1`, surface `#F1E8D6`), darker shades for small
text/marks on tiles (`#404B65`, `#9A5230`), orange only as decoration, terracotta only for a holder's bad news and the
弱点 card, system trouble as a navy triangle. Scores as five squares (empty = outline) plus the number. Numbers in
DINish. Dark follows the phone setting. Cover (`smallestScreenWidthDp < 600`): bottom tabs, list → detail. Inner: rail +
list + detail; the selection survives folding (activity handles config changes).

## Data contract

The app reads `index.json` → `weekly`, `scores_all.json`, `track.json` from `BuildConfig.DATA_BASE_URL` (empty = bundled
sample in `assets/sample`, shown with a 見本データ banner). See `Model.kt`; unknown keys are ignored, breaking changes go
under `/v2/`. Sample data is generated by a script (fake companies 0001–0012).

## Pipeline status (2026-11-07)

`pipeline/kabu/`: `companies` (JPX list, NFKC names), `tdnet` (list pages, UTF-8 now), `news` (Google News outlet
counts), `trending` (longest-name matching, short katakana names need a business word, max 5 per industry),
`pipeline` (`daily` / `weekly` / `merge`), `validate` (schema + rules, no advice words). Routine instructions:
`pipeline/prompts/evaluate.md`. Workflows in `.github/workflows/`. Published data and the working state
(`out/_state/`) live on the gh-pages branch. Not yet: prices, EDINET, fundamentals, track record (need the secrets).
Run locally with a venv outside the repo; tests: `python -m pytest pipeline/tests`. No git repo or GitHub remote yet.

## Planned pipeline (from the 2026-11-07 engineer review)

- Actions daily ~6:17 JST, no AI: JPX list (monthly), TDnet list HTML, EDINET (350/360 large holdings, 120 annual-report
  CSV), prices (stooq needs an API key since 2026-03; yfinance as fallback), Google News RSS outlet counts → JSON on
  GitHub Pages. Publish only own scores, counts, headlines and links, never raw price series or article text.
- Actions Saturday early: pick the 10, write `dossiers/<date>/*.json`.
- Routine Saturday ~7:00: read dossiers, write evaluations, validate against a JSON Schema, push to `claude/eval-<date>`;
  an Action checks, merges, publishes and posts to Discord through a webhook (secret in Actions only).
- Secrets (EDINET key, stooq key, Discord webhook) live only in GitHub Actions secrets; the owner has to create them.
- Open: owner OK for publishing the evaluations on a public GitHub Pages site; app name; weekly run time.
